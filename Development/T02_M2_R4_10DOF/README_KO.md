# T02 M2 R4 유지 / 10DOF / 하체 슬림 / 교감 리액션

2026-10-26 · R4-10DOF-0.1 · 외형·운동학 및 소프트웨어 검토본

## 변경 결과

R4의 머리·상체 외형, 좁아진 어깨 간격, 어깨 전방 8mm 이동과 좌우 대칭 15° 장착 각도를 유지했습니다. 모터 구성은 R3와 같은 양팔 각 4축 + 목 yaw 1축 + 허리 yaw 1축 = **상체 총 10축**입니다. 좌우 주행 모터 2개는 이 10축에 포함하지 않습니다.

|부위|구성|
|---|---|
|오른팔 4축|어깨 앞뒤 들기, 어깨 옆 벌리기, 팔꿈치 굽힘, 손목 굽힘|
|왼팔 4축|오른팔과 동일|
|목 1축|좌우 회전|
|허리 1축|좌우 회전|

R4에서 추가했던 상박 twist 2축과 목 pitch 1축은 제거하고 고정 연결 프레임으로 바꿨습니다. 따라서 모터로 고개를 끄덕이거나 상박을 비트는 기능은 없습니다. 교감 표현은 고개 좌우 회전·팔 동작·표정·음성으로 구성합니다. 목 2축을 유지하면서 양팔 대칭 4축과 허리 1축까지 유지하면 11축이 되므로 이번 10축안에는 적용하지 않았습니다.

## 하체 폭 7.5% 축소

|측정 항목|변경 전 R4|변경 후|
|---|---:|---:|
|하체 외피 최대 폭|353.9mm|327.4mm|
|바퀴 피벗 간격|361.0mm|333.9mm|
|오른쪽 바퀴 부품 폭|28.24mm|28.24mm|
|가슴 외피 최대 폭|250.0mm|250.0mm|

하체 외피·바닥판·범퍼·바퀴 커버의 폭을 줄였습니다. 바퀴 중심은 안쪽으로 옮기되 바퀴 자체의 지름·폭을 축소하지 않았습니다. 외피에 붙는 나사·스위치·포트는 크기를 유지하고 좌우 위치를 옮겼습니다. 앞뒤 캐스터 위치와 하체 높이·깊이는 유지했습니다. LUMIRA 문자는 결합 외피와 함께 폭 방향으로 축소됩니다.

수치는 GLB 메시/피벗에서 측정했습니다. 이 방식은 외형 비교용이며 기존 벽 두께를 보장하는 제조 CAD가 아닙니다. 배터리·모터·보드·커넥터·프레임과의 내부 공간, 바퀴-커버 간격, 허리 접합부와 전도 안정성을 확인한 뒤 최종 내면/체결부를 다시 설계해야 합니다. 내부 부품이 들어가지 않으면 7.5%안을 강행하지 않고 5%안 또는 내부 재배치를 비교합니다.

## 사용자와 교감하는 입력 구성

|입력|배치/방식 제안|리액션|
|---|---|---|
|카메라|기존 머리 카메라 활용, 로컬 얼굴 위치 검출|사용자 방향으로 목 yaw; 최초 인사|
|거리 센서|전면 ToF, 좌우 사각지대는 추가 센서 검토|접근 거리 확인, 지나친 근접에서는 새 동작 중지|
|손 터치|양손 연질 표피 안쪽 정전용량 전극|가벼운 접촉에 happy 표정|
|손 압력|양손 손바닥 내부 압력 센서/FSR + 탄성 완충층|손 잡힘 판정, affection 표정·짧은 음성|
|과부하|손목/구동기 전류 또는 별도 힘 센서|상위 교감 로직보다 먼저 정지 요청|
|범퍼·낙하 입력|하체 전면 접촉부와 바닥 방향 센서|충돌/탁자 가장자리에서 정지 요청|

센서는 구조·배치 제안이며 실제 장착한 상태가 아닙니다. ToF 후보 예시는 ST VL53L1X 계열이며, 부품과 기판의 전원·시야각·주변광·커버 영향은 실제 장착 조건에서 선정합니다. 한 개 센서로 로봇 주변 전체를 감시할 수 없습니다. 압력 센서 수치는 연질 손의 두께·경도에 영향을 받으므로 실제 손 부품에서 접촉/해제 임계값을 교정해야 합니다. FSR만으로 정확한 접촉력을 얻었다고 간주하지 않습니다.

센서 MCU가 ADC/터치 입력과 유효 상태를 읽어 `touch`, `pressure_contact`, `overload`, `valid`를 상위 컴퓨터에 전달하는 구조를 제안합니다. T02의 TX2 NX + J202에는 USB/UART 등으로 연결하되 실제 MCU·전압·프로토콜은 아직 확정하지 않았습니다. 이 패키지에는 MCU 센서 드라이버나 모터 통신 드라이버가 포함되지 않습니다.

## 손 잡았을 때의 반응

1. 압력 접촉 신호가 들어오면 즉시 해당 팔에 `CONTACT_YIELD_REQUEST`를 냅니다. 확인 시간 동안에도 새 팔 동작을 요청하지 않습니다.
2. 250ms 이상 지속되면 손 잡힘으로 확정합니다. affection 표정 ID와 “손을 잡아 주셨네요. 반가워요.”라는 음성용 문장을 한 번 출력합니다.
3. 잡힌 동안에는 해당 팔을 흔들거나 당기는 동작을 만들지 않습니다. 허리와 바퀴도 움직이지 않습니다. 양손이 잡히면 정면을 봅니다.
4. 접촉 해제 신호가 350ms 지속되면 grateful 표정과 “고마워요.” 문장을 출력합니다. 팔을 자동으로 뒤로 당기지 않고 다음 동작을 기다립니다.
5. 과부하·비상정지·낙하·충돌·센서 장애는 교감보다 우선합니다. 정지 후에는 정상 신호가 돌아와도 자동 재시작하지 않고 명시적인 reset 입력을 기다립니다.

`CONTACT_YIELD_REQUEST`는 하위 제어기에 보내기 위한 의미적 요청입니다. 실제 저토크/순응 제어를 실행한 것이 아닙니다. 비역구동 감속기에서 단순히 목표 위치를 멈추는 것만으로 사용자가 편하게 손을 움직일 수 있는 것은 아니므로 구동기 특성에 맞는 전류 제한·순응 제어를 구현해야 합니다. 단순 전원 차단도 팔 낙하를 일으킬 수 있어 별도 검토가 필요합니다.

기본 리액션은 로컬 이벤트로 처리합니다. ChatGPT API 응답이 늦더라도 접촉·과부하 정지가 지연되지 않도록 분리합니다. 표정 출력은 기존 R5의 neutral/happy/listening/affection/grateful ID에 연결하고, 음성 문장은 기존 TTS 모듈로 넘기는 구성입니다. 이 패키지 자체는 실제 화면 표시나 TTS 재생을 실행하지 않습니다.

## 카메라 코드 범위

`src/camera_input.py`는 OpenCV 4.x Haar 얼굴 검출기를 이용하는 로컬 시제품 코드입니다. 정확히 한 개의 얼굴 후보가 세 프레임 연속 안정적으로 검출될 때 방향 목표를 출력합니다. 복수 얼굴·미검출이면 새 방향을 내지 않습니다. 개인 식별, 나이·성별·감정 추정, 이미지 업로드·저장은 하지 않습니다.

기본 수평 시야각 60°와 yaw 방향 부호는 시험용 가정입니다. 실제 카메라 보정이 필요합니다. `quality_pass`는 연속 검출 조건을 통과했다는 의미이지 확률이나 인식 정확도가 아닙니다. Haar 검출은 옆얼굴·조명·가림에 취약할 수 있어 상용 인식 품질을 검증한 결과가 아닙니다. 실물 카메라는 이번 작업에서 연결 시험하지 않았습니다.

## 실행

Python 3.12 가상환경에서 `python -m pip install -r requirements.txt`로 의존성을 설치합니다.

```text
python src/test_interaction.py
python src/validate_model.py
python src/interaction.py < config/demo_input.jsonl
python src/camera_input.py --camera 0 --hfov 60 --yaw-sign 1
```

카메라 실행 명령은 사용자가 실행했을 때에만 해당 카메라를 엽니다. 카메라 JSON을 센서 스냅샷의 `camera` 필드에 결합하는 상위 통합부는 연결 대상 장치에 맞춰 구현해야 합니다. 모든 타임스탬프는 동일한 호스트의 단조 증가 시계를 사용하고 MCU 수신 시각을 호스트 기준으로 기록합니다.

리액션 계획기는 표준입력 JSON 한 줄당 결과 JSON 한 줄을 출력합니다. 예제 입력과 손 잡기/해제 결과는 config/demo_input.jsonl, results/hand_hold_demo.json에 있습니다. 실제 모터 출력은 항상 false입니다. 센서 스냅샷 유효시간 500ms, 근접 정지 0.25m 등은 시제품 설정값이며 실제 로봇 정지 성능에 대한 보증값이 아닙니다.

모델 재생성: `python src/build.py`. 비교 그림: `python src/render.py`(EGL/OpenGL 필요). GLB에는 인사·양팔 호응·손 잡힘 시 고개만 반응하는 3개 애니메이션이 있습니다. 손 잡힘 클립은 중립 자세에서 팔이 정지된 시각 예시이며 실제 임의 자세의 접촉 제어를 검증하는 시험이 아닙니다.

## 검사와 미완료 항목

확인: 10개 동작축, 3개 클립, 하체 폭 7.5% 감소, 바퀴 자체 폭 유지, 궤적의 유한값·중립 복귀, 손 잡힘 미리보기의 팔 정지, 이벤트 로직 10개 단위시험. 카메라의 오프라인 시험은 results/camera_offline_test.json에 별도로 기록합니다. 첨부 영상 50초 이후 30프레임 시험에서 얼굴 후보 5프레임, 연속성 조건 통과 2프레임이었습니다. 이는 안정적인 사용자 추적 성능을 확보했다는 결과가 아니며 카메라 검출기 보강이 필요합니다.

미완료: 센서 실장/교정, 모터 제어기 연결, 실제 순응 제어, 실물 손 잡기 시험, 내부 공간·정밀 간섭·전도 안정성 검증, 새 10축 구성의 강화학습 재학습. R4 13축 학습 정책은 이 모델에 적용할 수 없으며 과거 R3 10축 정책도 어깨 프레임과 손목 축이 달라 그대로 재사용하지 않습니다. 이번 파일은 새 구조와 교감 입력을 검토하는 버전이며 학습 완료본으로 표시하지 않습니다.

참고 자료: ST VL53L1X 제품 문서 https://www.st.com/en/imaging-and-photonics-solutions/vl53l1x · OpenCV CascadeClassifier https://docs.opencv.org/3.4.19/d1/de5/classcv_1_1CascadeClassifier.html
