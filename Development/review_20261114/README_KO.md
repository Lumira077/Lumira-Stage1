## 다음 실행 순서와 완료 기준

1. F2002→F2003 프로필 변경/철회/삭제 이벤트: 영속 이벤트 순서·중복·재시작·옛 epoch 거절을 먼저 설계하고 테스트한다. 단순 polling을 ‘즉시 철회’로 표현하지 않는다.
2. T02/보호자 앱/통신/Kids의 현재 개발본별 회귀 명령과 소스 해시를 통합 목록으로 고정한다. 구버전 main으로 덮어쓰지 않는다. 별도 패키지와 모델 자산 확보가 선행되어야 한다.
3. 대화 제공자·취소·memory ticket 연결을 모의 gateway로 검증한다. 실제 API 호출 성공과 비용·지연은 별도 인수한다.
4. T02 10DOF 학습은 현재 관절/기구/모델 자산을 확보한 뒤 별도 실험으로 진행한다. 기존 13DOF 정책을 그대로 재사용하지 않는다.

위 후속은 이번 결과에 포함된 완료 작업이 아니다. H/W 작업이나 사용자 개입 요청 없이 가능한 범위부터 개발을 시작했고, 완료 증거가 있는 첫 수정 묶음을 제공한다. Jira Epic/Story의 전체 Done 전환은 하지 않았다.

## 재현

Python 3.11 이상, 저장소 루트에서:

```sh
python scripts/verify_all.py
```

결과: `artifacts/verification/summary.json`, 개별 22개 `.log`, Epic01~06의 별도 report.json. 기대값: tests=896, passed=true, actual_robot_test=false, release_ready=false. 장비·클라우드 계정은 필요 없으며 일부 HTTP 시험은 loopback 임시 포트를 사용한다.

기억 수정만 확인:

```sh
cd Epic-01/F2003/F2003-S02
python -m unittest discover -s tests -v
```

기대값: 34건 통과. 신규 3건은 만료 조회 실패, 만료 확인 실패의 삭제 이력, 재시작 및 옛 요청 재생 차단을 검사한다. 후속 S03/S04의 의존 소스 해시도 갱신하고 전체 회귀로 확인했다. 검증 집계는 [validation.json](validation.json)에 보관한다.
